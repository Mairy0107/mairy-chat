# Fix: register fails on HTTP with crypto.subtle.digest

## Bug (live)
User on http://47.96.247.246/chat/ register page gets red error:
Cannot read properties of undefined (reading 'digest')

## Root cause (confirmed)
frontend/src/auth.js machineFingerprint() always calls crypto.subtle.digest(...).
On non-secure context (HTTP IP, not localhost), crypto.subtle is undefined -> crash.
AuthView.vue register body includes machineFingerprint: await machineFingerprint().
Login already skips unlockIdentity when !window.isSecureContext; register path was not guarded.
Password auth is server-side BCrypt — WebCrypto is NOT required for register/login passwords.

ARCHITECTURE.md currently claims register fingerprint also calls crypto.subtle and should register in a secure context — that claim is outdated for live HTTP IP access and must be corrected after the fix.

## MUST fix

Prefer a stable non-subtle SHA-256 (pure JS) or equivalent fallback fingerprint still matching backend expectations (check AuthService / DTO: likely 64 hex chars). Do not break the 3-accounts-per-browser quota. Prefer reusing an existing saved fingerprint in localStorage.
2. Register + login + forgot-password must succeed on insecure HTTP for password auth. Do not require subtle for those flows.
3. Room E2EE / voice that truly need subtle: keep requiring secure context with clear Chinese error (existing e2ee.js pattern). Do NOT strip E2EE.
4. Surface friendly Chinese errors in AuthView instead of raw JS TypeError if any crypto path still fails.
