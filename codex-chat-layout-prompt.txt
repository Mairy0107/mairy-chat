# Rebalance chat layout — message list majority, compact composer + header

## Goal
User screenshot (open `codex-chat-layout-shot.png` in this repo root): DM chat shows message list as a **tiny strip**; composer (tall textarea + voice tip + footer) dominates vertical space. Same issue can hit ChatRoomView.

Fix ChatRoomView + DmChatView (+ shared `frontend/src/style.css`, and App header styles used on chat routes):
1. **Message list gets the majority of viewport height** (`flex-grow` / `flex: 1 1 0; min-height: 0; overflow-y: auto`).
2. **Shrink composer**: shorter textarea (few rows / lower min-height / max-height), compact voice row & tip, less padding/margins; keep composer **pinned at bottom** (sticky flex from commit `0c70b06`).
3. **Also squeeze the top area** so messages get more space:
   - App header (`Mairy Chat` / 大厅 / 退出): reduce margin, padding, link min-heights on chat routes (prefer scoped via `.app-shell:has(> .chat-panel) > .app-header` so lobby/auth look unchanged unless a tiny shared tweak is clearly better).
   - Chat panel title/status/返回大厅 row + tools/notices: tighter padding/gaps/margins; keep readable; do not remove stealth/E2EE notices.
4. Reasonable bubble typography; do **not** let composer dominate.
5. Keep room E2EE voice + DM plaintext voice behavior unchanged (record/preview/send/play).
6. Concise minimal Chinese UI; paper-card aesthetic; no big redesign.

## Known CSS smell (verify then fix — do not blindly paste)
In `frontend/src/style.css` after `0c70b06`:
- `.chat-panel > .composer { max-height: 60%; }` — composer can eat most of the panel; **remove or sharply lower** (e.g. ~35% hard cap only as safety).
- `.chat-panel .composer-body { flex: 1 1 auto; }` — lets composer body grow; prefer **flex-shrink: 0** / natural height, not grow.
- Global `textarea { min-height: 80px; }` — too tall for chat; scope a smaller min-height (and optional max-height) under `.chat-panel .composer textarea` (rows ~2–3).
- `.chat-panel > .message-list { flex: 1 0 15%; }` — odd basis; prefer `flex: 1 1 0; min-height: 0` and ensure base `.message-list { height: 45vh; min-height: 250px; }` is overridden inside `.chat-panel` so it does not fight flex.
- Large `.app-shell` / `.app-header` / `.panel` padding eats message space on chat routes — compact on chat routes only.

## Preferred approach
1. Keep vertical flex: app-shell (chat) → header (shrink) → chat-panel (flex 1) → context/tools (shrink, compact) → message-list (flex 1, scrolls) → composer (shrink 0, compact, pinned bottom).
2. Composer: short textarea; compact `.voice-tools` (smaller button min-height if needed, wrap tip to one muted line / smaller font); tighter composer padding/border spacing.
3. Preserve auto-scroll helpers in both views; key dialog; media queries for narrow screens.
4. Do not break lobby / auth / assistant layouts.
